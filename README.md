### Аналіз результатів (GIL)
1. **Чому потоки не прискорили роботу:** Через GIL (Global Interpreter Lock) у стандартному Python лише один потік може виконувати байткод у будь-який момент часу. Оскільки наша задача обмежена процесором (CPU-bound), потоки тільки додають накладні витрати на перемикання, але не дають паралелізму.
2. **Чому процеси прискорили:** Кожен процес має власний інтерпретатор Python і власний GIL, тому вони можуть працювати по-справжньому паралельно на різних ядрах процесора. Прискорення склало ~3.5x при використанні 4-8 воркерів.
3. **Закон Амдала:** Час на `merge` (послідовна частина) практично дорівнює 0 на цьому обсязі даних. Якщо збільшити корпус, частка `merge` зросте, і графік прискорення почне "виходити на плато".
4. **Ціна:** Процеси споживають трохи більше пам'яті (RSS), але на цих обсягах різниця незначна. Передача даних через `pickle` між процесами також має свою ціну, але вона компенсується швидкістю.
